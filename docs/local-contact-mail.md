# Локално изпращане от контактната форма

Изпращането е разрешено само при `npm run dev` (`NODE_ENV=development`).
Production build не активира изпращане към реална поща и API връща 503 извън dev.
Формата за подробно запитване с `kind="website"` остава демонстрационна.

## Стартиране

Docker Desktop трябва да работи. Проверете за конфликт на портовете преди
стартиране. Използвайте:

```powershell
npm run mail:up
npm run dev
```

Ако сайтът вече работи, не стартирайте втори dev процес.

Mailpit: <http://127.0.0.1:18025>. SMTP: `127.0.0.1:11025`.
Compose файлът `compose.mailpit.yaml` има отделен project, контейнер, мрежа и том
с префикс `saitena-website`. Портовете са достъпни само от локалния компютър.
SMTP няма конфигуриран relay и писмата остават в Mailpit. Не е необходим `.env`
или истински имейл акаунт. Публичните контакти от `.env` не се променят.

Писмата са от `contact@saitena.test` до `inbox@saitena.test`. Имейлът на
посетителя се използва за Reply-To, а не за From или свободно избран получател.
Не се изпращат автоматични писма до посетителя. Данните се пазят в отделния
Docker том `saitena-website-mailpit-data` (до 500 писма). Използвайте тестови данни.

## Поведение

Докато заявката се изпраща, полетата и бутонът са деактивирани, показва се
индикатор, а повторно изпращане от същата форма се блокира. Центриран диалог за успех се показва само
след като SMTP е приел писмото. Той следва светлата/тъмната тема, затваря се с бутон
или Escape и връща фокуса към бутона за изпращане. След успех формата се нулира; при грешка запазва
въведеното и позволява повторен опит. Известието е достъпно с клавиатура и екранен
четец. При прекъснат отговор не се прави автоматично повторно изпращане.

API проверява Origin спрямо Host (LAN проксито нормализира и двете), формата и
размера на заявката, дължините, имейла и контролни символи. Локалният лимит е
20 заявки за минута за процеса. Това не е production антиспам услуга.
Не се записват съдържанията на писмата в логовете на приложението.

## Проверки

Node 24 изпълнява TypeScript валидирането директно в тестовете:

```powershell
npm run test:contact
npm run test:contact:integration
npm run typecheck
npm run build
```

Интеграционният тест изисква сайта и Mailpit да са стартирани на горните портове.
Той изпраща само тестово писмо, оставя го за преглед и проверява действителното му
получаване през Mailpit API, включително кирилицата и Reply-To. Не изтрива писма.

Използвани са [SMTP транспортът на Nodemailer](https://nodemailer.com/smtp) и
[официалният Docker образ на Mailpit](https://mailpit.axllent.org/docs/install/docker/).
